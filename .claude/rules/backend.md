# Backend rules (server/)

.NET 10 Web API, EF Core 10 + Npgsql, FluentValidation, xUnit. Solution: `server/TabletopEvents.slnx`.

## Layers

```
TabletopEvents.Api/
  Services/<Name>Service/        HTTP endpoints (one folder per resource)
    <Name>Service.cs             [ApiController] class named <Name>Service
    <Request>Validator.cs        FluentValidation validator(s) for that service's request DTOs
  Repositories/<Name>Repository/ all EF Core / SQL access
    I<Name>Repository.cs         interface the services and validators depend on
    <Name>Repository.cs          EF Core implementation over AppDbContext
  Repositories/RepositoryRegistration.cs   AddRepositories() — register every repository here
  Validation/FluentValidationActionFilter.cs  cross-cutting: runs validators, returns 400 ProblemDetails
  Dtos/Dtos.cs                   request/response records shared by services and repositories
  Models/                        EF entities (no navigation properties)
  Data/                          AppDbContext, SeedData, design-time factory
  Migrations/                    generated by dotnet ef
TabletopEvents.Api.Tests/
  Services/<Name>Service/<Request>ValidatorTests.cs
  Repositories/<Name>RepositoryTests.cs
  Support/TestDb.cs              in-memory AppDbContext seeded from SeedData
```

## Services (`Services/<Name>Service/<Name>Service.cs`)

- The endpoint class is named `<Name>Service`, decorated `[ApiController]` + `[Route("api/...")]`, and derives from `ControllerBase`. `[ApiController]` is what makes ASP.NET discover it, so never drop it. Do not name classes `*Controller`.
- Namespace is `TabletopEvents.Api.Services.<Name>` (not `...Services.<Name>Service`, which would clash with the class name).
- Services depend only on repository interfaces and configuration. **No `AppDbContext`, no LINQ-to-entities, no `Microsoft.EntityFrameworkCore` using** in a service.
- A service action assumes its request DTO is already valid (the filter ran the validator). It only does: call repositories, map to the response, choose the status code (200/201/404/409).
- `CreatedAtRoute` uses a named route constant (`EventsService.GetByIdRoute`), not `CreatedAtAction` with a controller-name string.
- Configuration-derived values (e.g. `Store:Location`) are applied in the service, not the repository (`dto with { Location = … }`).

## Validators (`Services/<Name>Service/<Request>Validator.cs`)

- **Validation lives here and nowhere else.** The client performs no validation; it submits what the user typed and renders these messages. Every rule a user can trip (required, length, range, ordering, existence, ownership) must be a FluentValidation rule with a user-facing message.
- Request DTO properties are **nullable** (`string?`, `Guid?`, `int?`, `DateTimeOffset?`) so a blank field arrives as `null` and the validator reports it (`NotNull` / `NotEmpty` with a "… is required." / "Select a …" message) instead of a binding failure. Services use `!`/`.Value` after validation.
- Model-binding failures (a decimal for an `int?`, malformed JSON) are normalized by `Validation/BindingErrors.cs` into the same property-keyed shape with "Invalid value.", so the client never sees framework messages. `ApiBehaviorOptions.SuppressModelStateInvalidFilter` is on for that reason.
- One `<Request>Validator : AbstractValidator<<Request>>` per request DTO, living in the folder of the service that accepts it. Auto-registered (scoped) by `AddValidatorsFromAssemblyContaining<AppDbContext>()`.
- DB-backed rules (existence, ownership) go through repository interfaces via `MustAsync`, never `AppDbContext`.
- Use `.Cascade(CascadeMode.Stop)` on a property chain so one field reports one error (e.g. "Unknown format." not also "does not belong").
- Every message is a full sentence ending in a period; property names stay PascalCase (the client's `mapApiErrors` lower-camel-cases them).
- Do not add DataAnnotations to DTOs. `SuppressImplicitRequiredAttributeForNonNullableReferenceTypes` is on so FluentValidation reports required fields.

## Repositories (`Repositories/<Name>Repository/`)

- Only place that touches `AppDbContext`. Public surface is the `I<Name>Repository` interface; services and validators inject the interface.
- Read methods return DTOs projected in the query (`Select(new XDto(...))`) so only needed columns load. Filter/order **before** projecting into a record; EF cannot translate a `Where` on a constructor-projected record's member.
- Write methods take entities from `Models/` and call `SaveChangesAsync`. Concurrency-sensitive writes (e.g. `AddIfCapacityAsync`) own their transaction and execution strategy inside the repository.
- Return `null` (nullable DTO / `int?`) for "not found"; the service turns that into 404.
- Register every new repository in `RepositoryRegistration.AddRepositories()`.

## Data model

- FK properties are named after the target entity (`Game`, `Format`, `EventId`) exactly as in `SPECS.md`. Entities have no navigation properties; relationships are configured in `AppDbContext.OnModelCreating` and queries use explicit `join`s.
- Seed rows use constant Guids in `SeedData` (`HasData`), so they live in migrations. Tests reference them via `SeedData.GameIds.*` / `FormatIds.*`.
- Schema changes: edit models/config, then `dotnet ef migrations add <Name>` in `TabletopEvents.Api/`. Migrations apply automatically on startup.

## Tests (`TabletopEvents.Api.Tests/`)

- Mirror the API folders: `Services/<Name>Service/<Request>ValidatorTests.cs`, `Repositories/<Name>RepositoryTests.cs`.
- Validators: `FluentValidation.TestHelper` (`TestValidateAsync`, `ShouldHaveValidationErrorFor(...).WithErrorMessage(...)`), constructed with real EF repositories over `TestDb.Create()`.
- Repositories: real EF repository over `TestDb.Create()` (in-memory, seeded, transactions ignored). Each test class gets its own database; dispose it.
- Every new validator and repository gets a test class before it is considered done.

## Adding a resource

1. `Models/<Entity>.cs` + `AppDbContext` config (+ migration).
2. `Repositories/<Name>Repository/I<Name>Repository.cs` + `<Name>Repository.cs`, register in `AddRepositories()`.
3. `Services/<Name>Service/<Name>Service.cs` (+ `<Request>Validator.cs` for each POST/PUT DTO).
4. Tests for the validator(s) and repository.
5. `cd server && dotnet test TabletopEvents.slnx` must pass.

## Commands (run in `server/`)

```bash
dotnet test TabletopEvents.slnx                 # build + unit tests
dotnet run --project TabletopEvents.Api         # API on :5000 (needs Postgres: docker compose up db)
dotnet ef migrations add <Name> --project TabletopEvents.Api
```
